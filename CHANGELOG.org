#+title: Changelog

* Unreleased

** Edit-with-Emacs
- =Super+Ctrl+O= opens any text field in an Emacs buffer for editing
- Clipboard-based capture via =wl-copy --clear= sentinel + =wl-paste= polling
- Captured text passed directly to Emacs (no =clipboard-yank= race)
- Write-back via =Ctrl+V= (selection) or =Ctrl+A, Ctrl+V= (full text)
- Emacs minor mode: =C-c C-c= finish, =C-c C-s= sync, =C-c C-k= cancel
- IPC from Emacs to Tecla via existing nREPL server (bencode)
- =tecla.el= auto-loaded by =emacsclient -e= on first invocation
- Hooks for buffer lifecycle (set major mode per app, etc.)
- Spec: =docs/edit-with-emacs-spec.org=

** Bridge
- Replace blocking 3-second device rescan with inotify on /dev/input
- Disable kernel autorepeat on virtual keyboard (EVIOCSREP)
- Safety releases for dropped events - prevents stuck keys
- Key state de-duplication across multiple physical keyboards
- Filter virtual devices by phys path (catches ydotool, espanso, etc.)
- Reduced send_to_client poll timeout (50ms -> 5ms)

** Keyboard processing
- Modal menus support modifier+key entries (e.g., =[:shift :b]=, =[:ctrl :shift :x]=)
- Modifiers not emitted during modal mode - only used for menu matching
- Blocking I/O and queue-based event processing in Babashka reader
- Error handling around key callbacks with safety releases

** Window management
- =wm/focus-or-launch= accepts map ={:class ... :command ...}= (positional args still work)
- Hyprland: proper JSON parsing via cheshire (fixes focus-or-launch not finding windows)
- Hyprland: window actions work under a Lua config (0.55+), which rejects the hyprlang dispatch syntax; the syntax follows =configProvider= from =hyprctl status=
- GNOME: updated to same map signature

** HUD
- Grid layout for aligned key/description columns
- Vector keys render as =shift+b= in the overlay

** Config
- Auto-reload on file changes (polls =~/.config/tecla/= every 2s)
- Auto-copy =config.example.edn= on first run
- Example config updated to map-based =focus-or-launch= syntax
